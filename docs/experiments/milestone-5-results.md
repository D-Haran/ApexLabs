# Milestone 5 — interactive engineering application

Completed and verified on 2026-09-19. This milestone adds recorded engineering inspection;
Milestones 1–4 physics and the schema-v4 writer are preserved. The runnable client is
[`apps/dashboard`](../../apps/dashboard), with generated baseline and higher-grip sessions.

## Reproduced simulation evidence

The included baseline is regenerated by the production simulator at 5 ms physics and 20 ms
controller periods, following one settling lap. It matches the Milestone 4 reference:

- Circuit: **1,078.753695 m**; recorded lap: **50.710 s**.
- Sectors: **13.365 / 18.895 / 18.450 s**.
- Peak-utilization event: **RL, 775.031198 m**, simulation timestamp **85.935 s**, elapsed **35.000 s**.
- At that event the app shows approximately **51.7 km/h**, **6.2°** steering, **0%** throttle,
  **21%** braking; RL **0.94 kN** normal load, **−0.62 kN** Fx, **1.08 kN** Fy and **1.25 kN** capacity.
  These rounded displays come from recorded state/forces. The raw utilization is marginally above
  1 by floating-point rounding, as in the original M4 report; it is not a new physics result.
- Higher reference friction (μ 1.20→1.35), otherwise identical procedure: **48.845 s**, a
  **1.865 s** recorded gain. At the baseline peak location, B is approximately **1.296 s** ahead.
- Region 700–800 m: baseline interval **5.386 s**, higher-grip interval **5.168 s**. These times
  are derived from spatially interpolated recorded timestamps, not reintegrated speed.

The M4 zero-warmup sensitivity runs were 50.935/49.070 s. The demonstration uses matched settled
runs and labels them separately; it does not claim the old sensitivity laps had different times.

## Verification

Before implementation, Release CTest and all four existing Python validation programs were run
successfully. They regenerated their standard numerical artifacts. After the additive CLI exporter,
Release CTest again passed **5/5**, and UBSan CTest passed **5/5**. No core dynamics files changed.

`tools/python/replay/validate_export.py` checks both included sessions and generates an additional
session with **two timed laps after one warmup**. It verifies exact row joins, schema versions,
normal-load totals, force/capacity agreement with recorded utilization, lap/sector identities,
spatial monotonicity, seam coverage and adjacent-lap timestamp continuity.

The **30 Vitest tests** cover real fixtures, unsupported schemas, missing/blank/nonfinite fields,
duplicate columns, invalid paths, mismatched companions, lap results, scalar and wrapped-angle
interpolation, categorical fields, seams, endpoint clamps, shared snapshot identity, replay rates,
pause/restart/finish, frame-step, spatial seeks, multiple laps, known synthetic deltas, differing
grids, incompatible geometry, interval summaries, event ties/onsets, the real peak and real A/B gain.

The **8 Playwright tests** passed against the final production Vite build on port 4173:

1. Playback, pause stability, rate, restart and exact 5 ms frame-step.
2. Event, telemetry, track-map and timeline cross-seeking, shared chart cursors and exact finish.
3. All four cameras, force/load/axis/velocity overlays, tire selection and visual capture.
4. A/B comparison, negative time delta, interval inspection and invalid-region rejection.
5. Zoom persistence during playback, shift-drag pan retaining span, all 16 channels and time mode.
6. Real local file import and a visible unsupported-schema error.
7. Desktop resize at **1024×1000** and **1920×1000**, without horizontal document overflow.
8. Frame/seek/load measurement while comparing two laps and playing the recorded scene.

TypeScript and the Vite production build pass. The installed dependency audit reported zero
vulnerabilities. Vite reports the large Three.js-containing chunk (about 1.33 MB uncompressed /
385 kB gzip); this is retained as a packaging limitation, not hidden by changing the warning limit.

A timeline test caught a real floating-point edge: fixed 1 ms HTML slider quantization stopped
short of a non-grid maximum timestamp. Continuous slider input now reaches the exact final
recorded state. An overview-camera visual check caught depth fighting, corrected through camera
near-plane and presentation-layer separation. Neither correction changes telemetry or physics.

## Measured UI performance

Production build, Apple **M2 Pro**, 10 CPU cores, **16 GB RAM**, Chromium 153 headless,
ANGLE Metal renderer **Apple M2 Pro**. Viewport **1512×1100**, device pixel ratio 1.
Engineering follow camera, normal force overlays, A/B session loaded, five selected plots, 1×
playback. See the [raw measurement JSON](milestone-5-performance.json).

| Measurement | Result |
|---|---:|
| Rendered frame intervals | 300 |
| Average interval | **16.668 ms** |
| 95th percentile interval | **17.500 ms** |
| Mean selector seek + subscriber notification | **0.153 ms** |
| 95th percentile selector seek | **0.300 ms** |
| Seek to subsequent paint opportunity | **18.800 ms** |
| Baseline session load | **422.100 ms** |

Frame times are wall-clock intervals between R3F callbacks, including scheduling. They are not
GPU timer queries, CPU-only render duration, a claim of maximum possible FPS, or a sustained
endurance benchmark. Seek-to-paint uses two animation-frame callbacks after restoring the cursor;
it is an approximation to presentation latency, not an instrumented display/input measurement.
Load includes worker creation, local fetch, parse/validation and structured-clone delivery; it
excludes the first finished 3D frame. Browser caches and machine load affect repeat measurements.

The built-in Performance measurements panel and the browser suite reproduce this procedure.
The in-app Browser connection was unavailable (no browser registered); tests used a separate local
Playwright Chromium instance. No user browser session or external service was required.

## Remaining limits

The vehicle is an illustrative placeholder; no branded high-quality asset is bundled. Imported
models support scale/orientation/pivot adaptation but no named wheel/suspension rig. Self-contained
GLB/GLTF works through the adapter; external-resource GLTF packages need conversion to GLB.
Environment art, physical road elevation, suspension displacement and wheel rotation are absent.

The application requires WebGL2 and advances replay through the scene frame loop. If 3D is
unavailable, the error boundary preserves static telemetry inspection, but playback is unavailable.
Large object-array sessions require memory proportional to row count; parsing is off-thread but
streaming/columnar formats and million-row profiling are deferred. The demo files total about
18 MB and intentionally retain full recorded precision without source-code embedding.

Comparison currently uses **two** laps with identical geometry/reference offset, on shared interior
coverage only. Regions cannot cross the seam. Tire capacities/forces/utilization are interpolated
independently between recorded rows, so their mathematical identities are exact only at recorded
states. Lap duration always comes from the simulator. No invented sensor data, temperature,
pressure, suspension travel, fuel or RPM is displayed.
