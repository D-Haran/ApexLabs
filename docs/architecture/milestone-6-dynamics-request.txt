APEXLAB — MILESTONE 6
DYNAMIC VEHICLE PHYSICS, DRIVER MODE, VEHICLE-SPECIFIC
OPTIMIZATION & FINAL ENGINEERING EXPERIENCE

ApexLab Milestones 1–5.5 are complete.

This milestone is intended to transform ApexLab from a deterministic
lap simulator/visualizer into an interactive computational motorsport
laboratory.

DO NOT discard or silently rewrite the validated earlier models.

Preserve independently runnable:

    longitudinal model
    linear bicycle model
    nonlinear planar four-tire model
    existing feasible-lap simulator
    existing passive sprung-body approximation

Build the new systems alongside them and quantify differences.

The milestone must be completed in gated phases:

    Phase A — genuine 3D road contact and airborne dynamics
    Phase B — vehicle-specific P1 and MCL36-inspired models
    Phase C — tire/fuel/energy state

Do not move to a later phase while the current phase fails validation.


============================================================
PHASE A — STOP GLUING THE CAR TO THE ROAD
============================================================

CURRENT PROBLEM

The current sprung-body implementation effectively assumes continuous
road contact.

This is physically wrong over sufficiently sharp crests or during
sufficient vertical acceleration.

The road may PUSH on a tire.

It may not PULL a tire toward the road.

That unilateral-contact property must be modeled explicitly.


1. NORMAL CONTACT

Each wheel must have a contact state.

For wheel i:

    contact_i ∈ {airborne, contacting}

Normal tire/road force must satisfy:

    Fz_i >= 0

The road may never generate negative normal force merely to keep a
wheel attached.

Use a physically defensible vertical tire/contact model.

Conceptually:

    delta_tire = geometric tire compression

    if delta_tire > 0:
        Fz = tire_vertical_stiffness * delta
           + tire_vertical_damping * delta_dot
    else:
        Fz = 0

Use a smooth formulation where necessary for numerical stability.

Never clamp a calculated negative Fz back to a positive value.


2. BODY VERTICAL DYNAMICS

The new vehicle model must integrate real vertical body motion.

At minimum retain:

    global X
    global Y
    global Z

    roll
    pitch
    yaw

and corresponding linear/angular velocities.

Prefer quaternion orientation internally.

The existing planar X/Y/yaw state should remain available as a
simplified validated model.


3. UNSPRUNG MASSES

Add four wheel/unsprung vertical DOFs if computationally practical:

    z_u_FL
    z_u_FR
    z_u_RL
    z_u_RR

with:

    unsprung mass
    tire vertical stiffness/damping
    suspension spring/damper

This is preferable to treating the wheel contact point as rigidly
attached to the chassis.


4. AIRBORNE CONDITION

When suspension extension and tire geometry can no longer maintain
contact:

    Fz_i = 0

If all four tires lose contact:

the car becomes a free rigid body subject to:

    gravity
    aerodynamic forces
    aerodynamic moments

but:

    tire Fx = 0
    tire Fy = 0
    tire Fz = 0

until contact is regained.

Do not special-case “jump”.

It must emerge from the equations.


5. BALLISTIC MOTION

While fully airborne:

    m * a = gravity + aero

No road-normal constraint.

The trajectory must therefore become ballistic.

The car should naturally reconnect with the road if its trajectory
intersects the surface again.


6. LANDING

Landing must occur through tire/suspension compliance.

Do not teleport the chassis back to road height.

Track:

    tire compression
    suspension compression
    damper force
    vertical acceleration

A large landing should visibly compress the suspension.

Avoid numerical impulse explosions.


7. ROAD QUERY

Implement a physical road-surface query for each wheel contact point.

Given world wheel position:

return:

    surface point
    surface normal
    road material
    friction coefficient
    curb/road/grass/runoff classification

Track geometry must be queried independently at each wheel.

Do not assume all four tires occupy the same road plane.


8. CURBS

Curbs must have actual height geometry.

They may change:

    wheel vertical position
    normal load
    chassis roll
    tire contact

The renderer and simulator must use consistent curb geometry.


9. OFF-TRACK SURFACE

Manual driving requires leaving the ideal path.

Support at minimum:

    asphalt
    curb
    asphalt runoff
    grass

with configurable:

    mu
    rolling resistance
    roughness / vertical disturbance

Do not instantly reset the vehicle just because it leaves the track.

Barrier collision can remain a documented later limitation.


10. REQUIRED CREST TEST

Create a deterministic convex crest.

Sweep speed.

At low speed:
    all wheels remain in contact.

At sufficiently high speed:
    available normal reaction must approach zero and wheels/car
    should lose contact.

Demonstrate the transition quantitatively.

Report:

    speed
    vertical acceleration demand
    four Fz values
    airborne duration
    maximum height above road
    landing loads

16. F1 AERO MUST BE DIFFERENT

The F1 model must have a much stronger speed-dependent aerodynamic
component than the P1.

Implement an explicit aero map:

    downforce = f(v, frontRideHeight, rearRideHeight, pitch, DRS)

    drag = g(v, aeroSetup, DRS)

The actual coefficients will require engineering estimates because
McLaren does not publish the MCL36 aero map.

Clearly mark this.

Support aero-balance migration.

Do not use the P1's simple aero model.


17. GROUND EFFECT

The MCL36-inspired model should respond to ride height.

Implement a smooth approximate floor-effect map.

Very high ride height:
    reduced floor downforce

effective operating range:
    stronger downforce

extreme low ride / inappropriate attitude:
    optionally reduced/stalled performance if justified by the chosen
    approximate model

Document assumptions.


18. DRS

Support DRS as a real state for the F1 configuration.

When enabled:

    rear downforce decreases
    drag decreases

Do not simply add speed.


19. POWERTRAIN DIFFERENCES

P1:
    7-speed dual-clutch hybrid road-car architecture

F1:
    8-speed sequential racing gearbox
    2022 hybrid architecture

Gear ratios may be estimated/calibrated when proprietary values are
unavailable.

Display that distinction clearly.

PHASE C — FUEL, ENERGY, TIRE TEMPERATURE AND WEAR
============================================================

20. FUEL MASS STATE

Add:

    fuel_mass_kg

Fuel mass contributes to total vehicle mass.

Where the tank position is known/estimated, fuel burn may also alter:

    CG position
    axle loads

Do not show a decorative fuel bar.

The UI fuel bar must derive from this state.


21. FUEL CONSUMPTION

Model fuel mass flow from power demand.

For F1 obey the applicable fuel-flow envelope including the published
100 kg/h upper limit.

For P1, use an explicitly estimated engine-efficiency/BSFC map where
real data is unavailable.

Do not use road NEDC consumption directly as track consumption.


22. HYBRID ENERGY

F1 state should include at least:

    battery/ERS energy state

respecting:

    MGU-K power limit
    deployment/lap constraint
    recovery/lap constraint

P1 should include an approximate hybrid energy/SOC state if sufficient
public parameters can be sourced.

Unknown parameters must remain marked estimated.


23. TIRE THERMAL STATE

The target UI includes tire temperature.

Do not fake it.

Implement at least a simple physically meaningful thermal model per tire:

    tread/surface temperature

Prefer:

    surface temperature
    carcass temperature

if stable and justifiable.

Heating sources should include:

    slip/friction work
    deformation/load contribution

Cooling should include:

    air convection
    road conduction approximation

Parameters may be generic/calibrated.


24. TIRE WEAR

Add per-tire wear state:

    wear_i ∈ [0,1] or physically meaningful equivalent

Wear rate should depend on quantities such as:

    sliding/friction energy
    load
    temperature
    speed

Grip should depend on:

    tire temperature
    wear

Do not claim it is the proprietary Pirelli model.

Research has explicitly modeled F1 grip as dependent on tyre temperature
and wear in optimal-control studies; use this class of approach as
guidance, but document your implementation.


25. TIRE PRESSURE

Do not display pressure unless modeled.

If pressure is added, derive it from a thermodynamic/volume model or make
it a static setup value clearly marked as such.

PHASE E — DO NOT DRIVE THE CENTERLINE
============================================================

33. REMOVE THE CENTERLINE ASSUMPTION

The optimized solution must be free to use track width.

Do not encode:

    "turn left -> apex inside"

as a heuristic.

The line must emerge from optimization.


34. WHY

Racing line depends on:

    vehicle dynamics
    braking ability
    acceleration
    power
    tire limits
    aero
    corner geometry
    following corner
    following straight
    track width

Therefore the optimal P1 line and optimal F1 line should differ
naturally.


35. SPATIAL OPTIMAL CONTROL

Use track progress s as the independent variable where numerically
beneficial.

Decision states should support at minimum:

    lateral path position e_y(s)
    heading error
    longitudinal velocity
    lateral velocity
    yaw rate
    relevant body/suspension states

and controls such as:

    steering
    drive/brake
    gear / power request where appropriate
    DRS where allowed
    hybrid deployment where modeled


36. TRACK BOUNDARY CONSTRAINT

Do not constrain only the CG if sufficient vehicle dimensions are known.

Prefer a body footprint / safety-envelope constraint.

At minimum use:

    e_y + vehicle half-width + margin

against track boundaries.

Document approximation.


37. FASTEST-LAP OBJECTIVE

Primary mode:

    MINIMUM TIME

Minimize:

    T = integral dt

subject to full dynamics and constraints.


38. MULTI-OBJECTIVE OPTIMIZATION

The user must be able to select optimization targets.

Support presets:

    Fastest Lap
    Shortest Path
    Maximum Clearance
    Neutral Handling
    Platform Stability
    Minimum Fuel
    Tire Preservation
    Custom


39. SHORTEST PATH

Minimize geometric path length.

Do not call it fastest.


40. MAXIMUM CLEARANCE

Maximize minimum clearance from track limits or minimize a smooth
boundary-risk cost.

This should generally produce a more central/conservative path.


41. NEUTRAL HANDLING

Do not define oversteer/understeer as a vague label.

Construct a documented balance metric based on quantities such as:

    front vs rear normalized tire utilization
    front vs rear slip reserve
    yaw response error
    front/rear slip-angle relationship

Choose one defensible definition and document it.

The optimization target should minimize the selected imbalance metric.


42. PLATFORM STABILITY

"Keep the car most level" should correspond to a physical objective.

Penalize appropriately normalized quantities such as:

    roll angle
    pitch angle
    heave displacement
    roll/pitch rates
    suspension travel variation

Do not simply minimize steering.


43. MINIMUM FUEL

Minimize:

    fuel_mass_start - fuel_mass_finish

while satisfying a lap-time constraint or user-defined maximum time.

Otherwise the trivial solution is driving arbitrarily slowly.


44. TIRE PRESERVATION

Minimize a function of:

    total wear
    maximum individual-tire wear
    thermal excursions

again with an optional lap-time constraint.


45. CUSTOM OBJECTIVE

Implement normalized weighted terms:

    J =
        wt * J_time
      + wp * J_path
      + wc * J_clearance
      + wb * J_balance
      + ws * J_stability
      + wf * J_fuel
      + ww * J_wear

Each component must be normalized to a documented reference scale.

Never add raw seconds, meters, kilograms and degrees without
normalization.


46. PARETO MODE

Where practical support a Pareto sweep for competing objectives.

Examples:

    lap time vs fuel
    lap time vs tire wear
    lap time vs clearance

Display the resulting trade-off curve.

Do not pretend one weighted solution is universally "best".


47. VEHICLE-SPECIFIC OPTIMIZATION

Run the same track for:

    P1
    F1

The optimizer must use their actual selected model.

Compare:

    racing line
    braking point
    apex
    exit
    speed profile
    tire utilization
    aero utilization

The objective is to demonstrate why different cars should not produce
identical lines.

48. FORCE SEMANTICS

49. TRANSFORM

For each contact patch:

    [Fx_tire, Fy_tire, Fz]

then rotate by body/world orientation

then render the WORLD-space force vector originating at the actual
contact patch.


50. REAR WHEELS

Rear wheels may have:

    steering angle = 0

while still having substantial:

    Fy != 0

because their contact-patch velocity may have a nonzero slip angle.

This is physically expected.

Do not force the arrow to align with the wheel just because it is a
rear wheel.


51. CONSTANT-RADIUS TEST

Construct a steady left-hand corner.

Verify:

    sum tire lateral force points toward the required center of curvature

and that rear lateral tire forces have the correct sign.

Repeat mirrored right turn.

If arrows visually point opposite the physical force:

investigate whether the visualization currently displays the road
reaction with the wrong sign.

    World
